O Problema Sem Controlo de Versão

😰 Cenário Típico Sem Git

  • 📁 projeto_final.zip
  • 📁 projeto_final_v2.zip
  • 📁 projeto_final_v2_corrigido.zip
  • 📁 projeto_final_FINAL.zip
  • 📁 projeto_final_FINAL_mesmo.zip
  • 📁 projeto_backup_antes_mudanca.zip

Problemas Comuns:

  • ❌ Não sabe qual é a versão mais recente
  • ❌ Impossível colaborar eficientemente
  • ❌ Perda de código ao sobrescrever ficheiros
  • ❌ Sem histórico de mudanças
  • ❌ Conflitos ao trabalhar em equipa

Git - A Solução

✨

Sistema de Controlo de Versão Distribuído

O que o Git oferece:

  • ✅ Histórico Completo - Cada mudança é registada
  • ✅ Colaboração - Múltiplas pessoas no mesmo projeto
  • ✅ Branches - Trabalhe em funcionalidades isoladas
  • ✅ Reversão - Volte a qualquer ponto no tempo
  • ✅ Distribuído - Cada cópia é um backup completo
💡 Facto: Git foi criado por Linus Torvalds (criador do Linux) em 2005 para gerir o desenvolvimento do kernel Linux.

Característica Git (Distribuído) SVN/TFS (Centralizado)

Velocidade ⚡ Muito rápido 🐢 Depende da rede

Backup Cada clone é um backup Apenas servidor

Trabalhar com Branches

🌿 Branches = Desenvolvimento Paralelo

Comandos de Branch

# Listar branches git branch # Criar nova branch git branch nova-funcionalidade # Mudar para branch git checkout nova-funcionalidade # Criar e mudar (atalho) git checkout -b nova-funcionalidade # Eliminar branch git branch -d nova-funcionalidade
📌 Best Practice: Use branches para cada nova funcionalidade ou correção!
13 / 25

Merge - Combinar Branches

Processo de Merge

# 1. Mudar para branch destino (geralmente main) git checkout main # 2. Fazer merge da branch git merge nova-funcionalidade # 3. Eliminar branch após merge (opcional) git branch -d nova-funcionalidade

Tipos de Merge

  • Fast-forward: Histórico linear, sem conflitos
  • 3-way merge: Cria commit de merge
  • Squash: Combina todos os commits em um
⚠️ Conflitos: Quando o mesmo ficheiro foi modificado em ambas as branches, precisa resolver manualmente.

GitHub - Plataforma de Colaboração

🐙

GitHub.com

O que é o GitHub?

Plataforma de hospedagem de código (baseada em git) com funcionalidades sociais e de colaboração.

Funcionalidades Principais:

  • 📦 Repositórios - Públicos ou privados
  • 👥 Colaboração - Múltiplos contribuidores
  • 🔍 Code Review - Pull Requests
  • 📋 Issues - Gestão de tarefas e bugs
  • 📖 Wiki - Documentação do projeto
  • 🚀 Actions - CI/CD automatizado
  • 📊 Insights - Estatísticas do projeto

Em 2018, a Microsoft adquiriu o GitHub, um negócio avaliado em USD 7.5 bilhões.

Pull Requests (PR)

O que é um Pull Request?

Pedido para integrar mudanças de uma branch para outra, com revisão de código.

Workflow Típico

  1. 🔀 Fork - Copiar repositório para sua conta
  2. 🌿 Branch - Criar branch para mudança
  3. ✏️ Commit - Fazer mudanças
  4. 📤 Push - Enviar para GitHub
  5. 🔄 PR - Criar Pull Request
  6. 💬 Review - Discussão e ajustes
  7. ✅ Merge - Integrar mudanças

Benefícios dos PRs

  • Code review antes do merge
  • Discussão sobre mudanças
  • Testes automatizados
  • Histórico de decisões

Boas Práticas Git

📝 Commits:

  • ✅ Commits pequenos e focados
  • ✅ Mensagens claras e descritivas
  • ✅ Usar convenções (feat:, fix:, docs:)
  • ❌ Evitar "fix", "update", "changes"

🌿 Branches:

  • main/master - Código em produção
  • develop - Desenvolvimento ativo
  • feature/xxx - Nova funcionalidade
  • bugfix/xxx - Correção de bug
  • hotfix/xxx - Correção urgente

🔄 Pull Requests:

  • Título descritivo
  • Descrição detalhada das mudanças
  • Link para issue relacionado
  • Screenshots se relevante
  • Request review de colegas

Git Avançado

Rebase Interativo:

# Editar últimos 3 commits git rebase -i HEAD~3 # No editor: pick abc1234 Primeiro commit squash def5678 Segundo commit # Juntar com anterior reword ghi9012 Terceiro commit # Mudar mensagem

Cherry-pick:

# Copiar commit específico git cherry-pick abc1234

Bisect (Encontrar bugs):

git bisect start git bisect bad # Commit atual tem bug git bisect good v1.0 # v1.0 estava OK # Git vai navegando, você testa... git bisect good # ou bad git bisect reset
