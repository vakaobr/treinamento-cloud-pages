Kubernetes (K8s)

☸️

Plataforma de Orquestração de Containers

O que é Kubernetes?

Sistema open-source para automatizar deployment, scaling e gestão de aplicações containerizadas.

História:

  • 🏢 Criado pelo Google (baseado no Borg)
  • 📅 Open source desde 2014
  • ☁️ Agora mantido pela CNCF
  • 🌍 Padrão de facto para orquestração

Por que "K8s"?

K + 8 letras (ubernete) + s = K8s

Pod - Unidade Básica

🥜

Menor unidade deployável em Kubernetes

Características:

  • Um ou mais containers (geralmente um)
  • Compartilham rede e storage
  • Têm IP único no cluster
  • Efémeros por natureza

pod.yaml:

apiVersion: v1 kind: Pod metadata: name: nginx-pod labels: app: nginx spec: containers: - name: nginx image: nginx:alpine ports: - containerPort: 80
9 / 35

ReplicaSet

Mantém número desejado de réplicas de pods

apiVersion: apps/v1 kind: ReplicaSet metadata: name: nginx-replicaset spec: replicas: 3 selector: matchLabels: app: nginx template: metadata: labels: app: nginx spec: containers: - name: nginx image: nginx:alpine ports: - containerPort: 80
💡 Nota: ReplicaSets raramente são usados diretamente (não é uma boa prática, apesar de ser possível). Nesses casos, sempre use Deployments!

Ingress - Roteamento HTTP/HTTPS

Gestão de acesso externo a serviços

Benefícios:

  • SSL/TLS termination
  • Name-based virtual hosting

Namespaces - Isolamento Lógico

Organização e Multi-tenancy:

# Criar namespace kubectl create namespace development kubectl create namespace production # Usar namespace kubectl get pods -n development kubectl apply -f app.yaml -n production # Definir namespace padrão kubectl config set-context --current --namespace=development

Namespace no YAML:

apiVersion: v1 kind: Namespace metadata: name: staging --- apiVersion: apps/v1 kind: Deployment metadata: name: app namespace: staging # Deploy no namespace staging

Namespaces Padrão:

  • default - Namespace padrão
  • kube-system - Componentes do sistema
  • kube-public - Recursos públicos

Health Checks - Probes

Tipos de Probes:

  • 💚 Liveness - Container está vivo?
  • 🟡 Readiness - Pronto para receber tráfego?
  • 🚀 Startup - Aplicação iniciou? (K8s 1.16+)
spec: containers: - name: app image: myapp:v1 livenessProbe: httpGet: path: /health port: 8080 initialDelaySeconds: 30 periodSeconds: 10 timeoutSeconds: 5 failureThreshold: 3 readinessProbe: httpGet: path: /ready port: 8080 initialDelaySeconds: 5 periodSeconds: 5
18 / 35

Gestão de Recursos

Requests e Limits:

spec: containers: - name: app image: myapp:v1 resources: requests: # Mínimo garantido memory: "256Mi" cpu: "250m" # 0.25 CPU limits: # Máximo permitido memory: "512Mi" cpu: "500m"

QoS Classes:

  • Guaranteed - requests = limits
  • Burstable - requests < limits
  • BestEffort - sem requests/limits
💡 Best Practice: Sempre defina requests e limits para produção!

Azure Kubernetes Service (AKS)

☁️

Kubernetes Gerido no Azure

Benefícios do AKS:

  • ✅ Control plane gerido (grátis!)
  • ✅ Atualizações automáticas
  • ✅ Integração com Azure AD
  • ✅ Azure Monitor integrado
  • ✅ Autoscaling de nodes
  • ✅ Azure Container Registry

Criar Cluster AKS:

# Via Azure CLI az aks create \ --resource-group myRG \ --name myAKSCluster \ --node-count 3 \ --node-vm-size Standard_B2s \ --generate-ssh-keys # Obter credenciais az aks get-credentials \ --resource-group myRG \ --name myAKSCluster

Criando Chart Helm

Estrutura de um Chart:

mychart/ ├── Chart.yaml # Metadados do chart ├── values.yaml # Valores padrão ├── templates/ # Templates Kubernetes │ ├── deployment.yaml │ ├── service.yaml │ └── ingress.yaml └── charts/ # Dependências

values.yaml:

replicaCount: 3 image: repository: nginx tag: "1.21" pullPolicy: IfNotPresent service: type: LoadBalancer port: 80

Template com valores:

apiVersion: apps/v1 kind: Deployment metadata: name: {{ .Release.Name }}-deployment spec: replicas: {{ .Values.replicaCount }}

Autoscaling

Tipos de Autoscaling:

HPA - Horizontal Pod Autoscaler

Escala número de pods baseado em métricas

kubectl autoscale deployment nginx \ --cpu-percent=70 \ --min=2 \ --max=10

VPA - Vertical Pod Autoscaler

Ajusta resources requests/limits

Cluster Autoscaler

Adiciona/remove nodes do cluster

az aks update \ --resource-group myRG \ --name myAKS \ --enable-cluster-autoscaler \ --min-count 1 \ --max-count 5

Troubleshooting Kubernetes

🔍 Comandos de Debug:

# Pod não inicia kubectl describe pod pod-name kubectl logs pod-name --previous # Problemas de rede kubectl exec -it pod-name -- nslookup service-name kubectl get endpoints # Resource issues kubectl top nodes kubectl top pods # Events do cluster kubectl get events --sort-by='.lastTimestamp' # Debug com ephemeral container kubectl debug pod-name -it --image=busybox

Problemas Comuns:

  • ❌ ImagePullBackOff - Verificar nome da imagem e registry
  • ❌ CrashLoopBackOff - Verificar logs e liveness probe
  • ❌ Pending - Verificar resources e node capacity
  • ❌ No endpoints - Verificar selector labels
